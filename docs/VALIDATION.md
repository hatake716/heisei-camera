## 現行 0.4.0：表示後に年代を選ぶ

`0.4.0`（versionCode 5）は、「映す風景」の注意書き2文目とリンク貼り付けの入口・画面を削除し、結果画面に「年代を選ぶ」を追加した版です。年代は Google マップの「他の日付を見る」で選び、対応するパノラマのリンクを Android 共有で受け取ると、シャッターを挟まず結果へ切り替えます。アプリ内の年代一覧や、撮影年を指定する Embed API 呼び出しは実装していません。

この版で次を確認しました。

- `:app:assembleDebug`・`:app:testDebugUnitTest`・`:app:lintDebug` 成功。既存28テスト成功、Lint エラーなし。APK の署名検証も成功。
- Android 15 / API 35 の専用エミュレーターで、「映す風景」に説明1文と自動表示・しおりの項目だけが表示され、共有リンク貼り付けの入口がないこと。
- シャッター後の模擬 GPS 座標による自動表示と、結果の「年代を選ぶ」→案内→Google マップの起動。
- 有効なパノラマの共有 Intent を受け取ると、新規起動時も結果表示中も、シャッターなしで指定画像の結果へ進むこと。現在地の `location` を表示中に共有すると、受信した `pano` のみの表示へ置き換わること。
- Google 以外の未対応リンクを共有しても結果画面と対象パノラマを維持すること。回転後も同じパノラマを表示し、縦横とも「年代を選ぶ」が表示されること。
- 結果画面でカメラが停止し、「現在に戻る」でプレビューを再開すること。実際の Google 画像と帰属表示も画面で確認。
- エミュレーター内の APK とビルド出力がバイト単位で一致。SHA-256: `228b708815ff65d5bb2e05634b8e7f1101110a32b37e8640792af24c035cddcf`。

証跡は Git 管理外の `artifacts/era-*.xml`・`artifacts/era-*.jsonl`・`artifacts/era-e2e-results.txt` に保存しています。API キーを含めていません。新しい共有成功イベント・キャンセル・Activity 保存復元についてソースレビューも実施しました。

Google マップの初期案内を進めた際にエミュレーターのプロセスが終了（終了コード139）したため、Vulkan を無効にして再起動し、アプリの上記確認を完了しました。その後の Google マップでの確認でもエミュレーターが終了したため、それ以上の再試行は行っていません。Google マップ内での年代一覧・年月変更・共有往復と、選んだ年代が共有後も保たれることは未検証です。既知のパノラマ ID の表示成功とは区別します。実機は未接続のため、この版は実機へインストールしていません。

## 0.3.0：現在地の自動取得の記録（参考）

`0.3.0`（versionCode 4）は、カメラプレビューからシャッターを押し、前景で位置を取得して「現在地の Street View」を表示する変更です。自動取得は最古・平成などの撮影時期を保証しません。手動で取り込むパノラマと既存のしおりも保持します。

この版で次を確認しました。

- `:app:assembleDebug`・`:app:testDebugUnitTest`・`:app:lintDebug` 成功。28テスト成功、Lint エラーなし。
- Android 15 / API 35 の専用エミュレーターで、保存済みの手動選択があっても起動時は自動モードとなり、リンク入力なしでシャッターから位置権限の確認へ進むこと。
- 位置権限の拒否・端末の位置情報オフで案内を表示し、以前の画像へ切り替えないこと。使用中の位置権限の許可後に測位して結果を開くこと。
- シャッター後に模擬 GPS 座標を入力し、Embed の `location` に取得座標が渡され、`pano` が混在しないこと。スイスのサンプル地点からパリへ位置を変更し、次のシャッターで新しい座標が使われること。
- 縦・横画面で実際の Google 画像と帰属表示を描画し、回転後も同じ検索座標を保持すること。
- 取得途中で Home を押すと位置取得がキャンセルされ、`dumpsys location` の現在の登録一覧からアプリのリスナーが消えること。復帰後に取り消した測位結果で画面を切り替えないこと。
- 結果画面・バックグラウンドでカメラを停止し、「現在に戻る」で再接続すること。
- 手動の共有リンクでは元の `pano` のみを指定し、現在地への代替を行わないこと。しおりの追加・保持と、自動モードへの切り替えを確認。
- 位置データの有限値・範囲・精度・単調時計の時刻をテストし、要求前の古い位置や未来の時刻を受け付けないこと。
- APK の署名を検証し、Pixel 10a へ上書きインストール。端末内の APK がエミュレーターで検証した APK とバイト単位で一致することを確認。バージョンは `0.3.0`（versionCode 4）。実機での入力操作や位置権限の代理許可は行っていません。

証跡は Git 管理外の `artifacts/location-*.jsonl`・`artifacts/location-*.xml`・`artifacts/location-e2e-results.txt` に保存しています。通信確認の記録には API キーを含めていません。実機の GPS・ネットワークや「おおよその位置情報」での測位、15秒の待機上限まで測位できない実環境の確認は未実施です。以下の旧版の結果とは分けて記録します。

## 現行版で確認する項目

1. 新たに起動すると現在地からの自動取得が標準になり、以前の手動選択が自動取得を上書きしないこと。
2. カメラの許可とライブプレビュー開始後、シャッターが位置取得を開始すること。必要な場合にだけ位置権限を求めること。
3. 位置権限の拒否、端末の位置設定が無効、測位失敗を案内し、設定変更や再試行へ進めること。以前の画像やサンプル画像へ代替しないこと。
4. 測位成功時に取得座標を使い、結果を「現在地の Street View」と表示すること。最古・平成の画像だと表示しないこと。
5. 結果画面とバックグラウンドでカメラを使用せず、「現在に戻る」でプレビューを再開すること。バックグラウンドの位置追跡を行わないこと。
6. 結果画面の「年代を選ぶ」から Google マップを開けること。Android 共有で受信したパノラマへシャッターなしで切り替わり、未対応リンクでは元の結果を維持すること。既存のしおりを維持し、自動取得の結果を特定画像のしおりとして保存しないこと。
7. API キー未設定・Google の画像取得失敗を、成功した風景表示として扱わないこと。
8. 写真やスクリーンショットを生成せず、独自の日付表示がなく、Google が提供する日付・ロゴ・帰属表示を隠さないこと。

エミュレーターの模擬座標による位置取得と実画像表示、実機の GPS・ネットワークによる現在地取得は分けて記録します。Google Cloud の実際のキー制限設定と、許可外オリジンでの拒否は引き続き別の確認項目です。キーの設定方針は [実現性と設計判断](FEASIBILITY.md) を参照してください。

## 手動選択のみの 0.2.1 の記録（参考）

以下は現在地の自動取得を追加する前の版で確認した内容です。この版では手動で選んだ画像を表示し、位置情報は利用していませんでした。

撮影年月の取得・独自表示を取り除き、Maps Embed API 用キー1つの構成へ変更しました。`0.2.1`（versionCode 3）で次を確認しました。

- `:app:assembleDebug`、`:app:testDebugUnitTest`、`:app:lintDebug`：成功。Lint はエラーなし、既存の依存更新案内等の警告あり。
- ユニットテスト20件成功（共有 URL 13件、Embed HTML 5件、古いページ通知2件）。年月機能専用のテストは削除。
- 年月表示・metadata 通信・追加キーの BuildConfig 設定をソースから除去。ローカルの認証情報ファイルは変更していない。
- Android 15 / API 35 の専用エミュレーターで、使い方案内、縦横の結果画面の UI 階層に独自の年月表示がないことを確認。
- シャッターで結果画面へ切り替わる際のカメラ切断、「現在に戻る」で再接続を `dumpsys media.camera` で確認。
- デバッグ APK の署名を `apksigner` で確認。

上記の撮影年月削除時の検証では Embed 用の設定値を含むビルドを使用しましたが、キーの有効性や Google の画像表示は判定していません。Google の画像はキャプチャせず、アプリ側の UI 階層とカメラ接続状態を確認しています。証跡は Git 管理外の `artifacts/no-date-*.xml`・`artifacts/no-date-*.txt` に保存しています。変更前の結果は下の旧版記録として保持します。

### 実キーの認証と空白画面の調査

- ローカルの有効なキー設定が空欄ではなく、実行に使用したビルドの値と一致することを確認。キーの値は検証記録へ記載していません。
- `https://appassets.androidplatform.net/` をオリジンとした実キーの Embed リクエストが HTTP 200 を返すことを確認。
- 実際の Android WebView で Google 公式サンプルのパノラマを指定すると、Google の iframe 内に操作 UI が生成され、認証エンドポイントが HTTP 200 を返すことを確認。認証エラーは確認されませんでした。
- 過去の UI テストで使用した `heisei-verification-pano` は実在する画像の ID ではありません。この ID に対する HTTP 400 は、有効な画像を指定していないことによる失敗であり、API キーの認証失敗として扱いません。
- WebView のウィンドウ寸法が約 388 × 491 CSS px でも、ラッパー HTML の `html`・`body` の高さが0となっており、Google のページが読み込まれても画面が空白になる状態を確認しました。WebView の既定の `WRAP_CONTENT` に対し、明示的な `MATCH_PARENT` の指定を追加しています。

修正後は次を確認しました。

- `:app:assembleDebug`・`:app:testDebugUnitTest`・`:app:lintDebug` 成功。既存の20テストはすべて成功。
- Android 15 / API 35、WebView 124 の専用エミュレーターで、共有リンク取り込み → ライブカメラ → シャッター → Street View の画像表示を確認。画像と Google の帰属表示を実際の画面で確認しました。
- 縦画面で約 388 × 491 CSS px、横画面で約 635 × 304 CSS px。ラッパー body と iframe が表示領域全体に広がり、高さが0にならないことを確認。
- 現在のカメラへ戻った際のカメラ再接続、2回目のシャッターでの切断、再表示と回転後の画像表示を確認。
- キーを伏せた DOM・通信・寸法の記録は Git 管理外の `artifacts/auth-*.jsonl` に保存。

公式サンプルは認証・読み込み・描画の切り分け用であり、利用者が選んだ過去画像や平成の最古画像を取得できた証拠ではありません。

今回の確認では Google Cloud の設定画面を変更していません。現在のキーがどの API・オリジンに制限されているか、および許可外のオリジンを拒否するかは未確認です。許可したいオリジンから認証が通ることと、拒否側の制限が機能することは別々に確認します。
